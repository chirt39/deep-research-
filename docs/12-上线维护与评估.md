# 上线维护与评估方案

## 本地完整运行

```powershell
Copy-Item .env.example .env
# 在 .env 中填写 DEEPSEEK_API_KEY
docker compose up -d redis postgres milvus
python -m uvicorn app.app_main:app --host 127.0.0.1 --port 8000
```

生产模式建议：先在 `.env` 中替换 `POSTGRES_PASSWORD` 和 `AUTH_TOKEN`，再执行 `docker compose up -d --build`。Redis/PostgreSQL 不映射宿主机端口，只允许 Compose 内部访问。

## 云服务器部署

第一阶段选择一台 4C8G 以上 Linux 云服务器，使用 Docker Compose 单机部署。Caddy/Nginx 负责 HTTPS，后端只绑定本机地址，Redis/PostgreSQL/Milvus 不暴露公网端口。`AUTH_TOKEN` 必须配置，生产数据库密码必须通过 `.env` 或 secret 注入。

## 监控指标

- API：请求数、状态码、P95 延迟、超时率。
- Agent：节点耗时、LLM 调用次数、输入/输出 token、估算成本。
- RAG：网页/本地召回数量、来源类型、平均可信度、引用覆盖率。
- 业务：报告质量分、补搜次数、报告失败原因。

## 评估闭环

`evals/cases.jsonl` 保存固定问题；`scripts/evaluate_report.py` 对报告做确定性回归。后续接入 Langfuse 或 LangSmith 时，将离线评估和线上 trace 分开：离线用于版本回归，线上用于异常检测和生产反馈。
