# 企业知识库 + 网络研究模式

## 为什么要改

原项目已经是金融多 Agent 投研系统，但不少规则、章节和免责声明写死了金融场景。这样能展示 Agent 编排，却不能证明系统具备可复用的 AI 应用工程能力。

本次改造把“研究域”变成请求级参数：`auto`、`general`、`finance`。默认自动识别，用户也可以显式指定。核心链路不变，但规划、写作、质量检查和报告元数据不再强制套用金融模板。

## 新链路

```text
用户问题 + research_domain
        |
        v
运行时研究域解析
        |
        +--> general: 动态章节 + 企业资料/网页研究
        |
        +--> finance: 宏观/行业/公司/估值/舆情 + 金融数据
        |
        v
LangGraph 规划 -> Web Scout || Local RAG -> Evidence Judge
        -> Analyst -> Reflect/补搜 -> Writer -> Quality Check
        |
        v
报告 + report_id + evidence_summary + trace + 引用列表
```

## 面试可讲的差异化能力

- 同一套工作流支持不同研究域，而不是复制两套 Agent。
- 质量检查根据研究域切换，避免“通用问题却要求投资评级”的模板错配。
- 返回 `report_id`、来源数量、来源类型、平均可信度和节点轨迹，前端/运维可以定位一次运行。
- 评估集独立于在线服务，可在改 Prompt、改模型或改检索器后做回归。
