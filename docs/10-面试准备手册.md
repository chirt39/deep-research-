# DeepResearch 面试准备手册

> 用途：把项目讲清楚、扛住追问的速查手册。先看 01（架构）/ 02（工作流）/ 03（节点）理解细节，
> 再回到本手册练习表达。所有"数字"都能在代码和测试里找到出处，不要背不解释的数字。

## 1. 一句话定位

本地可部署的**金融多智能体深度投研平台**：输入股票代码或研究问题，
9 个 LangGraph Agent 自动完成「意图路由 → 五维拆解 → 并行检索（网页 + 金融数据 + 本地知识库）
→ 证据裁判 → 分析研判 → 补搜迭代 → 研报撰写」，全程结论绑定可溯源引用，
单次成本约 1–3 分钱（界面实时显示 token 用量与估算成本）。

## 2. 数字速查表（每个都要能解释出处）

| 数字 | 含义 | 解释口径 |
|---|---|---|
| 9 | LangGraph 节点 / Agent 数 | intent 规则直判，evidence_judge 默认程序化，真正调 LLM 的是 6 个 |
| 5 | 五维分析框架 | 宏观 / 行业 / 公司 / 估值 / 舆情，质量自检按此查覆盖 |
| 2–3 分钟 | 单次研报耗时 | 默认 `MAX_ITERATIONS=2`；减到 1 轮约 2 分钟 |
| 0.01–0.03 元 | 单次成本 | token 启发式估算 + 单价配置，前端"本次研究"可见 |
| 0.40–1.00 | 证据可信度区间 | 程序化评分 5 档；`LLM_EVIDENCE_JUDGE=true` 时走 LLM 6 级标准 |
| 4 | 搜索计划上限 | 大纲定向词优先，通用兜底词最多 2 条（修过的 bug：兜底词曾挤掉定向词） |
| 30 | 每 IP 每分钟限流 | `RATE_LIMIT_PER_MINUTE`，防被刷 DeepSeek 额度 |
| 31 | 单元测试数 | pytest + GitHub Actions CI，含 Graph 级冒烟测试与报告历史测试 |
| 0–100 | 报告质量自检分 | 结构 / 引用 / 篇幅 / 维度覆盖四项 |

> 新增能力一句话：内置常见 A 股/港股/美股名称→代码映射；港股/美股支持历史行情；
> 报告历史本地留存（前端可回看/下载）；可选 LLM-as-Judge 双层质检；Docker 前端为生产构建（nginx）。

## 3. 架构一页纸（讲法）

```
前端 Vue3 ──SSE──▶ FastAPI（鉴权+限流+请求日志）
                        │
                        ▼
              LangGraph StateGraph（Checkpointer 可断点续跑）
  intent → plan → (web_search ‖ local_rag) → deep_dive → analyze
              ↑                                    │
              └──── reflect（最多 N 轮补搜）◀──── needs_more
                                                    │
                                              write → 质量自检 → final
```

三条数据源：DuckDuckGo/Bocha（网页）、AKShare（行情/财务/新闻/宏观）、Milvus（本地知识库）。
默认路径全部免费、无需付费 API。

## 4. 关键技术决策（每个能讲 30 秒）

1. **为什么用 LangGraph**：状态通道 + 条件路由 + Checkpointer（中断恢复）+ 并行边；
   自己写状态机要同时管状态合并、并发和持久化，LangGraph 把这些变成框架能力。
2. **为什么 evidence_judge 默认程序化**：LLM 判分慢（4–8s）、贵、不稳定；
   程序化规则（域名分级 + 关键词相关性）快、可解释、可测试；想更细可开 `LLM_EVIDENCE_JUDGE`。
3. **怎么防幻觉**：证据池 + source_id 绑定 → 写作时正则校验引用（非法引用直接剔除）→
   低置信度标记 + 冲突审计 → 参考资料由系统按正文实际引用拼接，不是 LLM 自己编。
4. **怎么控成本**：JSON 节点降 max_tokens（1024–2048）、迭代上限、预算 `max_sources`、
   搜索/金融缓存、跳过 LLM 证据整理、token/成本统计可视化（可量化"便宜"）。
5. **怎么保证质量**：写完自动质量自检（0–100 分）+ 引用校验 + 生成时间/免责声明。
6. **并发与安全**：同 thread 串行锁、AUTH_TOKEN、限流、默认只监听 127.0.0.1、.dockerignore 防密钥进镜像。

## 5. 高频面试题 Q&A

**Q1 介绍一下你的项目（三版）**
- 30s：输入股票代码，9 个 Agent 自动产出带引用溯源的投研报告，全免费数据源，单次约 1–3 分钱。
- 1min：加链路（意图→规划→并行检索→证据裁判→分析→补搜→写作）和两个工程点（引用校验、成本/质量统计）。
- 3min：加架构图 + 一个具体案例（比亚迪估值）+ 一个取舍（程序化裁判 vs LLM）+ 一个缺陷。

**Q2 哪些是你自己做的？**
诚实回答：架构与工程决策（并行、缓存、程序化裁判、引用校验、预算约束、降级设计、测试）是我做的；
代码实现和文档有 AI 辅助，我负责验证、调试和迭代。面试官更在意你能不能讲清"为什么这么设计"。

**Q3 为什么是 9 个 agent，不是越多越好？**
分工明确 → 可并行；但每个 LLM 节点都加延迟和成本，所以能规则化的（intent、evidence）就程序化，
能省调用的就省（默认跳过 LLM 证据整理）。

**Q4 引用一定是真的吗？**
证据先绑定 source_id，写作时只允许引用合法 ID，非法引用会被正则剔除；
参考资料列表由系统拼接。残留风险是网页内容本身有误，所以有可信度评分和交叉验证规则。

**Q5 搜索计划怎么生成？**
Planner 产出大纲和每节检索词 → 系统做"定向词优先 + 兜底词限 2 条 + 去重 + 上限 4"。
这里修过一个 bug：兜底词曾把定向检索词挤掉，导致检索变浅。

**Q6 太慢了怎么办？**
并行（搜索+金融数据同时跑）、程序化裁判、token 分级、缓存、迭代上限；还有 LLM_EVIDENCE 开关可调精度/速度。

**Q7 数据源挂了怎么办？**
DDG→Bocha 自动降级、AKShare 统一安全包装（失败返回错误记录、跳过不阻塞）、搜索/金融缓存、全程容错。

**Q8 成本怎么算的？**
字符启发式估 token（中文约 0.7 token/字），乘可配置单价（默认 1/2 元每百万），
每次研究按节点分项记录并在前端展示——不是拍脑袋的数字。

**Q9 记忆系统怎么实现的？**
三层：短期（Redis/Postgres 消息）、长期（Postgres/SQLite 用户画像+事实）、语义（Milvus 向量检索）。
注意默认 `enable_memory=false`，演示跨会话记忆要先开。

**Q10 项目有什么缺点？（主动暴露）**
① 港股/美股财务数据不支持；② 公司名→代码解析依赖搜索计划里带代码；③ 程序化评分比 LLM 粗糙；
④ 报告质量自检是规则式，不是模型评估。每个都给改进方向。

**Q11 和 ChatGPT Deep Research 比有什么不同？**
免费数据源、金融领域五维框架、引用可逐条点击验证、本地知识库 + 记忆、成本可视化；深度和规模当然比不了。

**Q12 再给你两周做什么？**
港股/美股数据、公司名→代码映射表、模型评估报告质量（LLM-as-Judge）、报告历史管理、并发压测。

## 6. 诚实边界（必看，防翻车）

- 项目有 AI 辅助开发成分，别把"从零手写"挂嘴边。
- 简历写"6 级可信度评分（0.40–1.00）"要能解释：程序化路径是 5 档，LLM 裁判路径才是 6 级。
- "9 个 Agent"指 LangGraph 9 个节点，其中 2 个默认不调 LLM。
- 演示前确认 DeepSeek Key 有效、网络通畅；AKShare 偶发被限流是正常现象。

## 7. 3 分钟演示脚本

1. 打开前端 → 输入"比亚迪 002594 估值分析"（0:00）
2. 指着进度区讲链路：意图→规划→并行检索→裁判→分析→写作（0:40）
3. 报告出来：指摘要、引用编号、参考资料（1:40）
4. 展示底部"本次研究：N 次调用，约 ¥X ｜ 质量自检 X/100"（2:20）
5. 收尾：讲一个取舍（程序化裁判）+ 一个缺陷（2:50）

## 8. 简历写法提示

- 数字用：9 个 Agent、2–3 分钟、0.01–0.03 元/份、24 项测试、质量自检 0–100。
- 动词用：编排、并行化、设计引用校验、实现成本统计、自动化测试。
- 一句话差异化：**全免费数据源 + 引用可溯源 + 成本可量化**，这是多数课程项目没有的。
